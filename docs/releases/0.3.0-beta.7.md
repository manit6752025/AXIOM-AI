# AXIOM AI v0.3.0-beta.7 — Release Notes

**Version:** `0.3.0-beta.7`  
**Tag:** `v0.3.0-beta.7`  
**Release channel:** Beta prerelease  
**Repository:** https://github.com/manit6752025/AXIOM-AI

Beta.7 consolidates the AXIOM-native local inference engine, CLI and Control Center workflows, safer runtime diagnostics, model registry improvements, and cross-platform release preparation.

## Highlights

### 1. AXIOM Native Engine and Local Inference

- Expanded AXIOM-owned local causal language model inference for supported Llama, Mistral, Qwen2 and Qwen3 safetensors checkpoints.
- Added GGUF support through the native Model Studio path where the checkpoint and runtime combination is supported.
- Added native model and LoRA adapter discovery under explicitly configured trusted roots.
- Added adapter compatibility preflight, model unloading, device and memory-mode selection, generation telemetry and cooperative cancellation.
- Exposed temperature, top-p, top-k, min-p, repetition penalty, seed and stop-sequence controls through the native API, CLI and Runtime UI.
- Added streamed token output and `axiom engine run --stream`.
- Preserved the existing non-streaming command path.
- Kept local inference separate from cloud inference. Cloud provider requests still require explicit user consent.

### 2. Runtime Visibility and Resource Monitoring

- Added bounded, metadata-only request tracing for local generation and benchmarking.
- Added request IDs, safe error codes, JSON export and explicit in-memory clearing.
- Prompt and generated-response bodies are not recorded.
- Added opt-in resource monitoring to the Runtime page, with CPU, RAM and process memory visibility.
- Limited browser-memory history to 120 samples.
- Added JSON export and clear controls.
- Added `axiom engine telemetry --watch`, supporting 1–300 samples and 0.5–60 second intervals.
- Added optional JSONL export without overwriting existing files.
- Runtime monitoring does not silently persist browser history.

### 3. Models, Datasets and Developer Workflows

- Expanded the model registry with source, licence and hash metadata.
- Added validated registry updates, import/export, filters, favourites, pagination and hardware-fit estimates.
- Expanded machine-readable CLI output for model, dataset, system, diagnostics, integration and registry operations.
- Strengthened dataset provenance, validation, safe workspace paths and privacy-minimised support bundles.
- Improved reusable workflow templates, revision history, duplication and validation.
- Added dry-run resource summaries without executing workflows.
- Kept the API Playground restricted to a predefined, bounded, read-only GET allowlist.

### 4. Release Engineering and Repository Improvements

- Synchronized Python runtime, Control Center, npm launcher, Scoop and WinGet version metadata to beta.7.
- Corrected active repository, installer, website and packaging references to the canonical AXIOM-AI repository.
- Retained historical beta.6 release records and tags.
- Repaired roadmap audit and release-smoke checks for the expanded 140-item roadmap.
- Hardened the weekly integration workflow to prepare subsequent beta versions without rewriting historical tags or leaving package manifests out of sync.

## Platform Support and Verification

The release workflow is configured to build:

- Windows x64
- Linux x64
- macOS Apple Silicon
- macOS Intel

Downloadable assets, checksums and installer-smoke results are authoritative only after the tag-triggered workflows complete successfully.

**Important:** The current macOS DMG and tarball packages are not Apple Developer ID signed or notarized.

## Known Limitations

- Native Engine support depends on checkpoint architecture, tokenizer, device and installed optional dependencies.
- Static build success does not guarantee every model and hardware combination works.
- Hardware-fit estimates are advisory.
- GGUF availability does not imply universal architecture or quantisation support.
- Runtime GUI history is held in browser memory only.
- CLI JSONL history is written only when an output path is explicitly supplied.
- The MCP server remains default-deny.
- Cloud LLM requests remain consent-gated.
- Workflow dry-runs and offline evaluation retain their documented execution boundaries.

## Installation

Install the Python prerelease:

```bash
python -m pip install --upgrade --pre axiom-all
axiom version
```
