# AXIOM AI v0.3.0-beta.8

**Release channel:** Beta prerelease  
**Version:** `0.3.0-beta.8`  
**Tag:** `v0.3.0-beta.8`  
**Repository:** https://github.com/manit6752025/AXIOM-AI

AXIOM AI beta.8 is a substantial update to the local-first AI development
platform. This release expands the Native Engine and local inference
workflows, improves workspace portability and data integrity, brings more
history and evaluation data into the API, CLI, and Control Center, strengthens
security boundaries, and advances the Python and TypeScript developer
experience.

AXIOM is designed around local ownership of models, data, and execution.
Local inference remains the default. Cloud-provider requests and optional
external integrations remain explicit and consent-gated; an optional runtime
or accelerator is not treated as available merely because it was requested.

## Release highlights

- **Native Engine:** broader supported Llama, Mistral, Qwen2, and Qwen3
  execution; batch generation; structured output; embeddings; reranking;
  prediction-job checkpointing and verified resume; and expanded benchmarks.
- **Knowledge and evaluation:** workspace-local knowledge bases, hybrid
  retrieval, versioned Prompt Studio templates, repeatable experiment
  comparisons, and persistent native benchmark profiles.
- **Workspace durability:** verified workspace backup and restore,
  content-addressed dataset snapshots, persistent telemetry, diagnostics,
  provenance inspection, and stronger filesystem protections.
- **Developer experience:** searchable cursor-paginated history, typed API
  page operations, improved CLI output modes, and Python and TypeScript SDK
  packages covering 30 API operations.
- **Security and supply chain:** SPDX SBOM generation, bounded local
  vulnerability scanning, declarative default-deny plugin manifests,
  dependency and artifact checks, and hardened path handling.
- **Control Center and website:** refreshed navigation, branding, responsive
  layouts, documentation, and release engineering workflows.

## 1. Workspace history, pagination, and CLI

- Added bounded cursor pagination and search for saved workflows and Model
  Studio job history across the API, CLI, and Control Center.
- Added paginated dataset and workspace-event inventories with typed client
  helpers.
- Added searchable, paginated runtime-trace history and older-page loading.
  Trace records remain metadata-only; prompts and generated responses are
  not stored in the trace buffer.
- Preserved existing array-based client helpers while adding typed page
  operations for clients that need cursor-based navigation.
- Added global CLI verbosity, quiet output, and structured JSON error modes.
- Tightened workflow search and cursor validation, documented error
  envelopes, and corrected verbose-mode logging behavior.
- Expanded read-only command JSON contracts and CLI/API/GUI navigation
  reference checks.

## 2. AXIOM Native Engine and local inference

- Expanded native local inference for supported Llama, Mistral, Qwen2, and
  Qwen3 checkpoint families, including validated sampling controls, stop
  sequences, grouped-query attention, RoPE scaling variants, KV-cache
  validation, and bounded prompt microbatching.
- Added native batch generation through the API, CLI, and Runtime page, with
  exact-length prompt bucketing, bounded device microbatches, per-prompt
  outputs, and cancellation.
- Added staged model acquisition, metadata-only readiness checks, explicit
  CPU/CUDA/ROCm/Metal/XPU selection, model unload, and resource cleanup.
- Added supported single-file and split-shard GGUF ingestion for native
  floating-point execution. GGUF quantized storage is dequantized for
  execution; this is not a low-bit inference kernel.
- Added bounded benchmarking with warm-ups, measured iterations, latency
  percentiles, throughput, and layer-streaming transfer counters.
- Added local prediction jobs with durable per-row checkpoints and
  integrity-verified resume across process restarts. Resume verifies dataset,
  model/adapter, generation settings, and checkpoint identity before
  continuing.
- Added JSON-Schema-constrained local inference with bounded schema and output
  validation.
- Added local safetensors embeddings and cross-encoder reranking adapters,
  exposed through the API, CLI, and Runtime interface.
- Added opt-in local image understanding using an Ollama model that explicitly
  advertises vision capability.
- Added local speech-to-text and text-to-speech using separately installed
  whisper.cpp and Piper components with user-supplied or trusted model assets.

## 3. Knowledge, prompts, and evaluation

- Added workspace-local knowledge bases with safe document ingestion, private
  copies, bounded indexes, content hashes, citations, and source-preserving
  deletion.
- Added bounded BM25 retrieval and optional local-vector score fusion, with
  deterministic chunking, metadata filters, query budgets, and citation
  offsets.
- Added versioned Prompt Studio templates with typed variables, validation,
  revision history, and literal-only rendering.
- Added repeated-evaluation comparison across immutable experiment snapshots,
  including comparability checks, replicate summaries, and inferential
  statistics only where defined.
- Added persistent native benchmark profiles with hardware/software
  provenance, bounded workload metadata, and run comparability checks.

## 4. Workspace portability, data integrity, and operations

- Added full-workspace ZIP64 backup and restore with versioned manifests,
  SHA-256 verification, bounded inventory, safe path and archive validation,
  private staging, and restore into a new workspace without overwriting the
  active one.
- Added content-addressed JSONL dataset snapshots with deduplication,
  append-only hash-chained manifests, lineage, source-change detection, and
  object verification.
- Added opt-in persistent resource telemetry with bounded retention,
  allowlisted CPU/RAM/process/device data, and privacy-selectable JSON/CSV
  export.
- Added workspace diagnostics, safer support bundles, schema inventory and
  migration documentation, and stronger path and symlink protections.
- Added model provenance inspection using bounded file hashing and local
  licence-evidence discovery. Registry claims remain identified as
  user-supplied unless independently verified.

## 5. Security and software supply chain

- Added SPDX 2.3 SBOM generation with bounded package inventory, normalized
  package URLs, deterministic fingerprints, and offline schema validation.
- Added a bounded local `pip-audit` scanner with isolated process
  configuration, output limits, duplicate-key rejection, and explicit
  unavailable and error states.
- Added declarative plugin manifests with schema validation, semantic-version
  updates, content fingerprints, exact-hash grants, revocation, and
  default-deny policy.
- Hardened filesystem path handling and MCP workspace fallback access so
  validated canonical paths are preserved through file operations.
- Expanded dependency advisory audits, package artifact inspection,
  cross-platform packaging checks, and filesystem-boundary regression tests.
- Retained default-deny MCP permissions, redacted audit data, explicit consent
  for cloud requests, and local workspace boundaries.

## 6. Python and TypeScript SDKs

- Implemented independent Python `axiom-ai-sdk` and TypeScript
  `@axiom-ai/sdk` packages with typed methods for 30 API operations.
- Added typed prediction-job resume results that expose dataset,
  model/adapter, generation-configuration, and checkpoint verification.
- Added shared OpenAPI operation registration and a cross-platform SDK
  contract and packaging matrix.
- Added publisher validation workflows that build and verify package
  artifacts without publishing them.

The SDK source packages are implemented. Publication to the PyPI and npm

## Compatibility and operational notes

- **Optional runtimes:** image and speech features rely on their separately
  installed local runtimes and compatible model assets. Their availability is
  detected rather than assumed.
- **Accelerators:** CPU execution and capability probes do not certify real
  CUDA, ROCm, Apple Metal/MPS, or Intel XPU execution on physical hardware.
  Hardware-specific validation should be completed on the target devices
  before relying on those acceleration paths in production.
- **GGUF:** supported GGUF files are executed through floating-point
  dequantization; this release does not provide a low-bit inference kernel.
- **Model support:** Native Engine compatibility depends on checkpoint
  architecture, tokenizer, device support, and the optional dependencies
  available in the environment.
- **Resource estimates:** hardware-fit and memory estimates are advisory and
  are not a substitute for measured calibration on the target system.
- **History retention:** Runtime GUI history is held in browser memory unless
  a feature explicitly persists a separate record.
- **macOS signing:** macOS DMG and tarball artifacts are not Apple Developer ID
  signed or notarized.
- **MCP and external services:** MCP access remains default-deny. Cloud LLM
  requests and optional external integrations remain consent-gated.
- **Model provenance:** locally discovered licence evidence and registry
  metadata are informational; user-supplied claims are not independently
  verified by the provenance inspector.

## Security and validation

AXIOM includes local security controls, dependency and artifact checks,
filesystem-boundary protections, and software-supply-chain tooling. SBOM and
scanner output should still be reviewed in the context of the actual build
environment. A scanner being unavailable or returning no findings is not a
guarantee that an environment is vulnerability-free.

Physical accelerator validation, repository security review, and SDK registry
publication are distinct from the feature implementation described above.
They should be evaluated against the target release and deployment
environment rather than inferred from successful CPU tests or package
validation workflows.
