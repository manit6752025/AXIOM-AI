# AXIOM AI v0.3.0-beta.8 — Release Notes (Draft)

> **Publication status:** Draft only. The `v0.3.0-beta.8` tag and GitHub
> release have not been published. The latest published prerelease remains
> `v0.3.0-beta.7`. Release assets and checksums must not be advertised as
> available until the tag-triggered release workflows finish successfully.

**Version:** `0.3.0-beta.8`  
**Planned tag:** `v0.3.0-beta.8`  
**Release channel:** Beta prerelease  
**Repository:** https://github.com/manit6752025/AXIOM-AI

Beta.8 consolidates the work delivered after beta.7 across the local Native
Engine, workspace data, developer tooling, the Control Center, security
boundaries, and release engineering. AXIOM remains local-first: local model
execution is the default, remote-provider use is explicit and consent-gated,
and optional runtimes and hardware are not represented as available unless
they have been detected and verified.

## Highlights

### 1. Workspace history, pagination, and CLI contracts

- Added bounded cursor pagination and search for saved workflows and Model
  Studio job history across the API, CLI, and Control Center.
- Added paginated dataset and workspace-event inventories with typed client
  helpers.
- Added searchable, paginated runtime-trace history and older-page loading.
  Trace records remain metadata-only; prompts and generated responses are
  not stored in the trace buffer.
- Preserved existing array-based client helpers while adding typed page
  operations.
- Added global CLI verbosity, quiet output, and structured JSON error modes.
- Tightened workflow search and cursor validation, documented error
  envelopes, and corrected the missing logging import in verbose mode.
- Expanded read-only command JSON contracts and CLI/API/GUI navigation
  reference checks.

### 2. AXIOM Native Engine and local inference

- Expanded native local inference for supported Llama, Mistral, Qwen2, and
  Qwen3 checkpoint families, including validated sampling controls, stop
  sequences, grouped-query attention, RoPE scaling variants, KV-cache
  validation, and bounded prompt microbatching.
- Added native batch generation through the API, CLI, and Runtime page, with
  exact-length prompt bucketing, bounded device microbatches, per-prompt
  outputs, and cancellation.
- Added staged model acquisition and installation, metadata-only readiness
  checks, explicit CPU/CUDA/ROCm/Metal/XPU selection, model unload, and
  resource cleanup.
- Added supported single-file and split-shard GGUF ingestion for native
  floating-point execution. GGUF quantized storage is dequantized for
  execution; this is not a low-bit inference kernel.
- Added bounded benchmarking with warm-ups, measured iterations, latency
  percentiles, throughput, and layer-streaming transfer counters.
- Added local prediction jobs with durable per-row checkpoints and
  integrity-verified resume across process restarts. Resume verifies dataset,
  model/adapter, generation settings, and checkpoint identity before
  continuing.
- Added JSON-Schema-constrained local inference with bounded schema and output
  validation.
- Added local safetensors embeddings and cross-encoder reranking adapters,
  exposed through the API, CLI, and Runtime interface.
- Added opt-in local image understanding using an installed Ollama model that
  explicitly advertises vision capability.
- Added local speech-to-text and text-to-speech using separately installed
  whisper.cpp and Piper components and user-supplied/trusted model assets.

### 3. Knowledge, prompts, and evaluation

- Added workspace-local knowledge bases with safe document ingestion, private
  copies, bounded indexes, content hashes, citations, and source-preserving
  deletion.
- Added bounded BM25 retrieval and optional local-vector score fusion, with
  deterministic chunking, metadata filters, query budgets, and citation
  offsets.
- Added versioned Prompt Studio templates with typed variables, validation,
  revision history, and literal-only rendering.
- Added repeated-evaluation comparison across immutable experiment snapshots,
  including comparability checks, replicate summaries, and inferential
  statistics only where defined.
- Added persistent native benchmark profiles with hardware/software
  provenance, bounded workload metadata, and run comparability checks.

### 4. Workspace portability, data integrity, and operations

- Added full-workspace ZIP64 backup and restore with versioned manifests,
  SHA-256 verification, bounded inventory, safe path and archive validation,
  private staging, and restore into a new workspace without overwriting the
  active one.
- Added content-addressed JSONL dataset snapshots with deduplication,
  append-only hash-chained manifests, lineage, source-change detection, and
  object verification.
- Added opt-in persistent resource telemetry with bounded retention,
  allowlisted CPU/RAM/process/device data, and privacy-selectable JSON/CSV
  export.
- Added workspace diagnostics, safer support bundles, schema inventory and
  migration documentation, and stronger path/symlink protections.
- Added model provenance inspection using bounded file hashing and local
  licence-evidence discovery. Registry claims remain identified as
  user-supplied unless independently verified.

### 5. Security and software supply chain

- Added SPDX 2.3 SBOM generation with bounded package inventory, normalized
  package URLs, deterministic fingerprints, and offline schema validation.
- Added a confirmed, bounded local `pip-audit` scanner with isolated process
  configuration, output limits, duplicate-key rejection, and explicit
  unavailable/error states.
- Added declarative plugin manifests with schema validation, semantic-version
  updates, content fingerprints, exact-hash grants, revocation, and
  default-deny policy.
- Expanded dependency advisory audits, package artifact inspection,
  cross-platform packaging checks, and filesystem-boundary regression tests.
- Retained default-deny MCP permissions, redacted audit data, explicit consent
  for cloud requests, and local workspace boundaries.

### 6. SDKs and API contracts

- Implemented independent Python `axiom-ai-sdk` and TypeScript
  `@axiom-ai/sdk` packages with typed methods for 30 API operations.
- Added typed prediction-job resume results that expose dataset,
  model/adapter, generation-configuration, and checkpoint verification.
- Added shared OpenAPI operation registration and a cross-platform SDK
  contract/packaging matrix.
- Added validate-only publisher workflows that build, install, and verify
  package artifacts without publishing them.

**SDK publication is still gated:** the PyPI and npm registry ownership,
Trusted Publisher/provenance setup, explicit owner authorization, and actual
publication/clean registry installation remain outstanding. These packages
must not be described as publicly published yet.

### 7. Control Center, website, branding, and release engineering

- Redesigned the public website with a centred full-screen layout, typed
  headlines, a galaxy hero, and new Integrations, Workflows, Downloads, Docs,
  Roadmap, Security, and Community pages.
- Added a dedicated Native Engine page and updated native model and generation
  documentation.
- Refreshed the branded 404 page, dark theme, responsive layouts, navigation,
  download layouts, Saturn mark, documentation banner, orbital monogram, and
  README banner.
- Added a workflow to synchronize `main` into maintained branches.
- Restricted GitHub Pages deployment to version tags or manual dispatch.
- Expanded release smoke and acceptance checks for pagination, API contracts,
  package contents, and cross-platform builds.

## Known limitations and outstanding gates

- Real CUDA, ROCm, Apple Metal/MPS, and Intel XPU adapter execution still
  requires successful runs on registered physical hardware. CPU execution
  and capability probes are not evidence of physical accelerator validation.
- A clean current-head CodeQL result and repository-owner disposition of
  remaining code-scanning findings are still required.
- The SPDX/SBOM feature still needs current-head CI/schema verification and
  controlled real-scanner tests for advisory, no-findings, and unavailable
  outcomes.
- Neither SDK has been published to PyPI or npm. Publication requires the
  configured publisher identities, explicit owner authorization, and clean
  installation from both registries.
- Hardware-fit and memory estimates are advisory, not measured calibration.
- Native Engine support depends on checkpoint architecture, tokenizer,
  device support, and installed optional dependencies. GGUF execution uses
  floating-point dequantization rather than a low-bit kernel.
- Runtime GUI history is held in browser memory unless a feature explicitly
  persists a separate record.
- macOS DMG and tarball artifacts are not Apple Developer ID signed or
  notarized.
- MCP remains default-deny. Cloud LLM requests and optional external
  integrations remain consent-gated.
