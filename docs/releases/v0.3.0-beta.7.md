# AXIOM v0.3.0-beta.7 — Release notes

**Version:** `0.3.0-beta.7`  
**Tag:** `v0.3.0-beta.7`  
**Channel:** Beta prerelease  
**Project:** [manit6752025/AXIOM-AI](https://github.com/manit6752025/AXIOM-AI)

Beta.7 consolidates the AXIOM-native local inference engine, its CLI and Control Center workflows, safer runtime diagnostics, model-registry improvements, and cross-platform release preparation.

## Highlights

### AXIOM Native Engine and local inference

- Expanded direct AXIOM-owned local causal-LM inference for supported Llama, Mistral, Qwen2, and Qwen3 safetensors checkpoints, with GGUF support through the native Model Studio path where the checkpoint/runtime combination is supported.
- Added native model and LoRA adapter discovery under explicitly configured trusted roots, adapter compatibility preflight, model unload, device and memory-mode selection, generation telemetry, and cooperative cancellation.
- Exposed generation controls such as temperature, top-p, top-k, min-p, repetition penalty, seed, and stop sequences through the native API, CLI, and Runtime UI.
- Added streamed token output and `axiom engine run --stream`, while preserving the existing non-streaming command path.
- Kept local execution separate from cloud inference. Cloud provider requests still require explicit user consent.

### Runtime visibility and resource monitoring

- Added bounded, metadata-only request tracing for local generation and benchmarking, with request IDs, safe error codes, JSON export, and explicit in-memory clear controls. Prompt and generated-response bodies are not recorded.
- Added resource monitoring to the Runtime page. Sampling is off until the user starts it, retains at most 120 browser-memory samples, shows CPU/RAM/process memory, and supports JSON export and clear.
- Added `axiom engine telemetry --watch` for explicitly requested resource sampling, bounded to 1–300 samples and 0.5–60 second intervals. Optional JSONL export creates a new file rather than overwriting an existing one.
- Resource histories are not silently persisted by the Runtime page. Leaving the page ends collection and discards its browser-memory history.

### Models, datasets, and developer workflows

- Expanded the model registry with source/license/hash metadata, validated updates, export/import, filters, favorites, pagination, and hardware-fit estimates.
- Expanded machine-readable CLI output for model, dataset, system, diagnostics, integration, and registry operations.
- Continued strengthening dataset provenance, validation, safe workspace paths, diagnostics, privacy-minimized support bundles, and request/error correlation.
- Improved workflow design with reusable templates, revision history, duplication, validation, and dry-run resource summaries. A dry-run remains a planning operation; it does not execute the workflow.
- Kept the API Playground constrained to a predefined, bounded, read-only GET allowlist.

### Release and repository preparation

- Synchronized the Python runtime, Control Center, npm launcher, Scoop, and WinGet version metadata to beta.7.
- Corrected active repository, installer, website, and packaging references to the canonical `manit6752025/AXIOM-AI` repository. Historical beta.6 release records and tags are retained.
- Repaired roadmap audit and release-smoke checks for the expanded 140-item scope.
- Hardened the weekly integration workflow so it can prepare later beta versions without rewriting historical tags or leaving package manifests out of sync.

## Known boundaries

- AXIOM Native Engine support depends on the checkpoint architecture, tokenizer, device, and installed optional dependencies. A successful static build does not prove every model/device combination works.
- Hardware-fit numbers and resource estimates are advisory; they are not a substitute for a measured run on the target machine.
- GGUF availability through Model Studio does not imply every GGUF architecture or quantization is supported by the native runtime.
- Runtime resource monitoring is opt-in and bounded. The GUI history is held in browser memory only; the CLI writes JSONL only when an output path is explicitly supplied.
- The MCP server remains default-deny. Cloud LLM requests remain consent-gated.
- Workflow design/dry-run and offline evaluation retain their documented execution boundaries.
