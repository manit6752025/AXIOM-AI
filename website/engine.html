01 / TWO DISTINCT CONNECTIONS

Native engine first.
Other runtimes optional.

AXIOM can use its own inference implementation or connect to supported local services. These are separate backends with separate status checks.

AXAXIOM-NATIVE

AXIOM Native Engine

Independent model loading, tokenization, forward pass, attention, KV cache, sampling and decoding implemented in AXIOM with PyTorch tensor kernels.

  • Does not start or call Ollama
  • Runs supported checkpoints from trusted local roots
  • Supports CPU and detected accelerator backends
  • Streaming, batch generation, estimates and bounded benchmarks
Native Engine technical guide ↗
OLOPTIONAL CONNECTOR

Ollama integration

Use Ollama as a separate local service when you want its model catalogue, GGUF runtime support, managed pulls and loaded-model inventory.

  • Uses the fixed loopback endpoint 127.0.0.1:11434
  • Requires Ollama to be installed for this backend
  • Model downloads happen only after an explicit pull action
  • Ollama status does not determine Native Engine readiness

02 / READ THE STATUS CORRECTLY

Ollama offline?
Native inference can still be separate.

If the Runtime panel says OLLAMA OFFLINE or “Ollama executable not detected”, that reports the optional Ollama connector. It is not a verdict on AXIOM Native Engine.

Check the native engine independently with axiom engine status. It reports dependency readiness and native model/runtime information. A model and the required native inference dependencies must still be installed before generation can run.

03 / WHAT RUNS LOCALLY

AXIOM owns the execution path.

MODEL FAMILIES

Llama · Mistral · Qwen

Supported dense Llama, Mistral, Qwen2 and Qwen3 text checkpoints, subject to implemented architecture and configuration constraints.

MODEL INPUT

Safetensors and GGUF

Safetensors checkpoints and supported GGUF files. GGUF tensors are dequantized to floating point for native execution; this is not a low-bit kernel.

DEVICE SELECTION

CPU and accelerators

Explicit or automatic selection across available CPU, CUDA, ROCm, Metal/MPS and Intel XPU backends, depending on the installed PyTorch build and hardware.

GENERATION

Streaming and sampling

Token streaming, stop sequences, reproducible seeds, temperature, top-k, top-p, min-p and repetition penalty with validated bounds.

MEMORY MODES

Plan before loading

Estimate weight, KV-cache and workspace memory. Supported modes include full loading and experimental layer/disk streaming with CPU KV-cache offload.

MEASUREMENT

Benchmark real runs

Bounded local benchmarks report latency, time to first token, throughput and applicable transfer counters. Results depend on the selected model and hardware.

Full install, model format and safety requirements ↗
Honest capability boundary

Native support is not universal model compatibility. EXL2, GPTQ/AWQ low-bit kernels, arbitrary remote model code, unsupported architectures and multimodal model variants are not implied. GGUF native execution currently dequantizes supported tensors to floating point. See the technical guide and release notes for exact supported behavior.
