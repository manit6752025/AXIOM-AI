# Code of Conduct

## AXIOM — NetCore Technologies

**Build AI. Own AI.**

This Code of Conduct describes the standards expected of everyone participating in the AXIOM project and the NetCore Technologies community.

We want AXIOM to be a place where people can build, learn, experiment, review ideas and improve software together.

---

## 1. Our standards

Participants are expected to:

- Treat other people with respect and professionalism.
- Communicate constructively, even when opinions differ.
- Give technical feedback based on the work rather than the person.
- Welcome people with different levels of experience.
- Be honest about testing, results, limitations and mistakes.
- Keep discussions focused on improving the project.
- Respect the time, effort and contributions of other community members.
- Protect private information, credentials and security-sensitive material.

Good technical disagreement is encouraged.

Personal attacks, harassment and hostile behaviour are not.

---

## 2. Expected behaviour

Examples of positive behaviour include:

- Explaining why a proposed change may cause a problem.
- Suggesting an alternative implementation.
- Asking questions before assuming intent.
- Giving useful code-review feedback.
- Acknowledging mistakes and correcting them.
- Sharing reproducible test results.
- Helping new contributors understand the project.
- Keeping issue and pull-request discussions relevant.

When discussing architecture, implementation or design, challenge the idea rather than the person.

---

## 3. Unacceptable behaviour

The following behaviour is not acceptable:

- Harassment, intimidation or personal attacks.
- Discrimination or hateful conduct.
- Threats of violence or deliberately threatening language.
- Sexual harassment or unwelcome sexual attention.
- Publishing private or identifying information without permission.
- Sharing passwords, private keys, tokens or other confidential credentials.
- Deliberate disruption of project infrastructure.
- Malicious interference with repositories, releases, CI systems or services.
- Repeatedly derailing technical discussions.
- Trolling or intentionally provoking other contributors.
- Impersonating maintainers or other community members.
- Retaliating against someone who makes a good-faith report.

Illegal activity connected to the project may be reported to the appropriate authorities where necessary.

---

## 4. Technical disagreement

AXIOM is an engineering project. Strong opinions about architecture, performance, tooling and implementation are normal.

Healthy disagreement should:

1. Identify the technical concern.
2. Explain the reasoning or evidence.
3. Propose alternatives where useful.
4. Stay focused on the project.
5. Stop when a maintainer or project decision has been made unless new evidence is available.

Arguments should not become personal.

---

## 5. Security and responsible disclosure

Security reports should not be posted publicly when they contain exploitable vulnerabilities, credentials or sensitive information.

Use the project's security reporting process:

https://github.com/manit6752025/AXIOM-AI/blob/main/SECURITY.md

Do not publish:

- Passwords
- API keys
- Access tokens
- GPG private keys
- Private certificates
- Sensitive network credentials
- Private datasets
- Exploit details that could enable immediate abuse

Good-faith security research and responsible disclosure are welcome.

---

## 6. Code review and contributions

Code review is part of the engineering process.

Reviewers should:

- Focus on correctness, security, maintainability and project requirements.
- Explain important requested changes.
- Avoid unnecessary personal criticism.
- Distinguish blockers from suggestions.
- Recognize good work as well as problems.

Contributors should be open to review and should not treat technical feedback as a personal attack.

See the project contribution guide:

https://github.com/manit6752025/AXIOM-AI/blob/main/docs/CONTRIBUTING.md

---

## 7. Scope

This Code of Conduct applies to project spaces and activities operated for AXIOM, including where applicable:

- GitHub repositories
- Issues
- Pull requests
- Discussions
- Code reviews
- Documentation
- Project chat or community spaces
- Official project events

Maintainers may take action when behaviour outside a project space directly affects the safety or ability of the AXIOM community to participate normally.

---

## 8. Reporting concerns

If you experience or witness behaviour that violates this Code of Conduct, report it to the project maintainers through an appropriate private channel.

For security vulnerabilities, use:

https://github.com/manit6752025/AXIOM-AI/blob/main/SECURITY.md

For general project issues, use:

https://github.com/manit6752025/AXIOM-AI/issues

Please provide enough context for the maintainers to understand what happened, while avoiding unnecessary disclosure of private information.

Reports made in good faith will be treated seriously.

---

## 9. Enforcement

Project maintainers may take reasonable action in response to violations, including:

- Asking for behaviour to stop.
- Removing inappropriate content.
- Closing or moderating discussions.
- Temporarily restricting participation.
- Removing access to project spaces.
- Taking other appropriate action to protect the project community.

The response will depend on the severity and context of the behaviour.

---

## 10. Good-faith participation

AXIOM is an open-source engineering project.

We encourage:

- Curiosity.
- Experimentation.
- Evidence-driven discussion.
- Clear documentation.
- Constructive criticism.
- Collaboration.
- Continuous improvement.

You do not need to agree with every decision to participate.

You do need to treat other people with respect.
