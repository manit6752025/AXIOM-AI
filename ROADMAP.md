## Product roadmap — 140 scoped deliverables

This backlog expands the ten original priorities into concrete, reviewable
deliverables. Preserve the existing Control Center navigation, visual language,
responsive layout, and keyboard behavior while extending its workflows. Items
are planned unless explicitly marked otherwise; scope is not a claim that the
feature exists or a delivery-date promise.

### 08 · Runtime, optimization, and quantization

- [R085 · Implemented; tests passing] Add passive runtime connector discovery and capability reporting without assuming a connection or credentials.
- [R086 · Implemented; tests passing] Add explicit connect/disconnect controls with secret-safe storage across the unified LLM client, managed Ollama service, and local Engine Fabric. LLM provider profiles are workspace-scoped with a browser-local metadata cache fallback; GUI, API, and CLI profile management never persists API keys, prompts, system instructions, or chat history. Custom LLM endpoints are restricted to public HTTPS `/v1` URLs without embedded credentials. Engine Fabric profiles store only a fixed backend ID and exact model ID in a bounded, private workspace store; GUI/API/CLI support save, list, one-shot verification, and delete. Connect verifies local loopback readiness and the exact model inventory but retains no socket, launches no process, and sends no credentials. Disconnect clears AXIOM's active prompt/model/result/benchmark state, retains saved profile metadata, and does not stop an external runtime; AXIOM-managed Ollama service controls remain the explicit start/stop path. Verified with 976 Python tests, 62 browser E2E tests, ESLint, TypeScript/production build, release smoke, and Ubuntu/macOS/Windows release-contract jobs (quality-gates run #44716149792). Remaining boundary: external Engine Fabric adapters are stateless fixed-loopback clients; they do not manage arbitrary endpoint URLs, credential vaults, or the lifecycle of unmanaged external processes.
- [R087 · Implemented; tests passing] Report native-engine dependency readiness, supported Llama/Mistral/Qwen2/Qwen3 floating-point safetensors checkpoints, public native-model acquisition with staged installs/progress, explicit CPU/CUDA/ROCm/Metal/XPU selection, loaded backend/architecture, and local-only execution scope. Native decoding now includes validated greedy/temperature sampling, exact-count top-k filtering, nucleus top-p, probability-relative min-p, repetition penalty, reproducible sampling seeds, and stop-sequence handling, wired through the native GUI, CLI, synchronous/streaming API, unified local LLM client, and compatible Engine Fabric routes. Experimental in-RAM layer-by-layer staging and disk-resident safetensors layer streaming with CPU KV-cache offload are available with transfer telemetry. Mistral sliding-window attention now retains a compact bounded KV suffix per layer while preserving absolute RoPE positions and context limits. Grouped-query attention passes compact KV heads directly to SDPA where `enable_gqa` is supported, with expanded-SDPA and manual-math compatibility fallbacks; regression coverage compares both paths with an expanded reference. Native forward calls now validate KV-cache layer count, K/V tensor shapes, head dimensions, model dtype, memory-mode device, positive and per-layer sequence lengths before tensor operations, with malformed-cache regression coverage. Native config loading rejects boolean/coercible dimensions, model_type/architecture mismatches, malformed BOS/EOS IDs, and invalid tied-embedding flags. RoPE now supports default, linear interpolation, Llama 3 wavelength-based scaling, YaRN frequency interpolation with validated attention scaling, and dynamic NTK scaling with a factor-derived effective context bound. Regression tests cover dynamic NTK frequency math/context limits and YaRN frequency/attention scaling; these native regression tests passed in the full Python suite (run #44725384748). Other RoPE scaling variants remain unsupported. Runtime forward inputs reject non-tensors, empty sequences, unsupported index dtypes, and prompt token IDs outside the checkpoint vocabulary before model execution. Native forward also supports fixed-length prompt microbatches and matching batched KV-cache decode, with equivalence tests against per-row execution; generation scheduling and variable-length continuous batching remain separate work. Native generate_batch() adds shared prefill/decode microbatching, per-row repetition penalties, independent EOS completion, and greedy or temperature/top-k/top-p/min-p sampling. Same-length prompt buckets are also split into bounded eight-sequence device microbatches to cap peak batch memory; responses retain input order and microbatch telemetry aggregates across chunks. This path is wired through a bounded `/api/engine/generate/batch` route, repeatable `axiom engine batch --prompt ...` and UTF-8 `--prompts-file` CLI inputs, plus a Runtime-panel batch form with per-prompt outputs and truncation/stop telemetry. Prompts with different lengths are bucketed into exact-length batches rather than naively padded; asynchronous continuous batching remains separate work. Rotary position embeddings are now computed once per forward sequence and shared by query/key projections across layers, avoiding repeated frequency-table work; checkpoint loading rejects non-floating embedding weights before selecting auto precision. Native checkpoint loading now also validates the vector dimensions of optional q/k/v/o and MLP projection biases plus an optional output-head bias before runtime execution; Qwen2 bias loading has a direct forward-pass regression test. Ordinary non-sliding prefill now delegates causal masking to SDPA without constructing a dense quadratic boolean mask, and single-token decode over a populated cache uses the all-available-key fast path; explicit masks remain for chunked and sliding-window attention. Cache, GQA and RoPE regression tests passed the full software CI and release-smoke run #44725384748 (991 Python tests and 62 browser tests). New readiness regressions cover missing/too-old required packages, optional GGUF dependencies, unavailable devices, accelerator recommendation priority, CPU fallback and loaded architecture/device/memory mode; API, CLI and GUI device-selection/forwarding checks also passed.
